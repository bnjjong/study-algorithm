# 121. Best Time to Buy and Sell Stock

- 난이도: **Easy**
- 링크: https://leetcode.com/problems/best-time-to-buy-and-sell-stock/
- 주제: 배열, 그리디 / 한 번 훑기

## 문제

`prices[i]`는 `i`일 째 주식 가격입니다.
**한 번 사고 한 번 파는** 거래로 얻을 수 있는 **최대 이익**을 반환하세요.

- 사는 날은 파는 날보다 **앞**이어야 합니다 (`buyDay < sellDay`).
- 이익을 낼 수 없다면 `0`을 반환합니다.

## 예시

```
입력: prices = [7, 1, 5, 3, 6, 4]
출력: 5
설명: 2일째 1에 사서 5일째 6에 팔면 6 - 1 = 5

입력: prices = [7, 6, 4, 3, 1]
출력: 0
설명: 가격이 계속 떨어지므로 거래를 안 하는 게 최선
```

- `1 <= prices.length <= 10^5`
- `0 <= prices[i] <= 10^4`

## 생각 거리

### Level 1 — 무식하게 (O(N²))
모든 (사는 날, 파는 날) 쌍을 시도해서 최대 이익을 찾기.
이중 for문. `prices.length`가 10⁵라서 10¹⁰ 연산 → **시간 초과 가능성 높음**. 제출 전 시간복잡도 검토 필수.

### Level 2 — 한 번만 훑기 (O(N)) ⭐ 면접 기대 정답

핵심 발상:
> "오늘 파는 게 가장 이득인 경우 = **지금까지의 최저가에 사서** 오늘 파는 것"

→ 배열을 **왼쪽에서 오른쪽으로 한 번만** 훑으면서:
1. 지금까지 본 **최저 가격(minPrice)** 을 갱신
2. "오늘 파는 경우의 이익(`prices[i] - minPrice`)"을 계산해서 최대 이익(maxProfit) 갱신

```kotlin
var minPrice = Int.MAX_VALUE   // 지금까지의 최저 매수가
var maxProfit = 0              // 지금까지의 최대 이익

for (price in prices) {
    // 1. 오늘 사는 게 더 싸다면 minPrice 갱신
    // 2. 오늘 판다고 가정한 이익을 계산해 maxProfit 갱신
}
return maxProfit
```

### 왜 이게 동작하는가
- "사는 날 < 파는 날" 제약 → **오늘을 파는 날로 볼 때, 사는 후보는 어제까지의 어떤 날이든 OK**
- 그 후보 중 **이익이 최대가 되는 사는 날 = 가장 싼 날**
- 그래서 한 번 훑으면서 "지금까지의 최저가"만 들고 다니면 충분

### 왜 이 패턴이 중요한가
**"한 번 훑으면서 최댓값/최솟값을 누적"** — 매우 자주 등장하는 패턴.
이 발상은 슬라이딩 윈도우, Kadane's algorithm(#53 Maximum Subarray), DP 입문(#198 House Robber) 등으로 확장됩니다.

## 실무에서 어디에 쓰이는가

실무 직접 응용 사례는 떠오르지 않음 — 알고리즘 패턴 학습용.
다만 "데이터를 한 번만 훑으면서 누적 통계를 갱신한다"는 발상 자체는 스트리밍 처리/모니터링에서 자주 보입니다.
